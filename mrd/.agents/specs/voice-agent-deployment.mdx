# Voice Agent API Deployment

> **STATUS: Pending DevOps**
> 
> The Voice Agent API endpoints are ready but require a new Vercel project deployment.

## Problem

The current `medplum-app` Vercel project uses **Vite (React SPA)** with root directory `packages/app`. This does not support Next.js API routes.

The Voice Agent API endpoints are located in `mrd/apps/medrecord/app/api/agent/` and require a **separate Vercel project**.

## Current Architecture

| Project | Framework | Root Directory | Domain |
|---------|-----------|----------------|--------|
| medplum-app | Vite (SPA) | `packages/app` | `medplum.healthtalk.ai` |
| medplum-server | ? | ? | `medplumapivercal.healthtalk.ai` |
| **voice-agent-api** | Next.js | `mrd/apps/medrecord` | **TBD** |

## Deployment Options

### Option A: New Vercel Project (Recommended)

Create a dedicated Vercel project for the Voice Agent API.

**Steps:**

1. Go to `vercel.com/new`
2. Select repository: `MEDrecord/medplum`
3. Configure:
   - **Root Directory**: `mrd/apps/medrecord`
   - **Framework**: Next.js (auto-detected)
   - **Build Command**: `npm run build` (default)
4. Deploy

**Domain options:**
- `agent.healthtalk.ai`
- `api.healthtalk.ai`
- `voice.healthtalk.ai`

### Option B: Add to medplum-server

If `medplum-server` is a Next.js project, add the API routes there instead.

### Option C: External Hosting

Deploy to Cloudflare Workers, AWS Lambda, or similar for more control.

## Required Environment Variables

Add these to the new Vercel project:

| Variable | Source | Required |
|----------|--------|----------|
| `ELEVENLABS_API_KEY` | ElevenLabs Dashboard | Yes |
| `ELEVENLABS_VOICE_ID` | ElevenLabs Dashboard | Yes |
| `KV_REST_API_URL` | Upstash Integration | For production |
| `KV_REST_API_TOKEN` | Upstash Integration | For production |
| `MEDPLUM_CLIENT_ID` | MedPlum Admin | For production |
| `MEDPLUM_CLIENT_SECRET` | MedPlum Admin | For production |
| `MEDPLUM_BASE_URL` | Known | For production |

**Note:** The API runs in **mock mode** without MedPlum/Redis credentials, returning test data. This is useful for initial testing.

## API Endpoints

Once deployed, these endpoints will be available:

```
POST /api/agent/questionnaire
POST /api/agent/answer
POST /api/agent/complete
```

## Post-Deployment: Update ElevenLabs Agent

After deployment, update the webhook URLs in ElevenLabs:

1. Go to ElevenLabs → Agents → "Vragenlijsten aan patient" → Tools
2. Update each tool URL to the new domain:

| Tool | New URL |
|------|---------|
| get_questionnaire | `https://{NEW_DOMAIN}/api/agent/questionnaire` |
| save_answer | `https://{NEW_DOMAIN}/api/agent/answer` |
| complete_questionnaire | `https://{NEW_DOMAIN}/api/agent/complete` |

## Post-Deployment: Update Twilio Webhooks

If using WhatsApp/SMS features, update Twilio sandbox settings:

| Setting | New URL |
|---------|---------|
| When a message comes in | `https://{NEW_DOMAIN}/api/webhook/twilio/whatsapp` |
| Status callback URL | `https://{NEW_DOMAIN}/api/webhook/twilio/status` |

## Testing

After deployment, test with curl:

```bash
# Test questionnaire endpoint (mock mode)
curl -X POST https://{NEW_DOMAIN}/api/agent/questionnaire \
  -H "Content-Type: application/json" \
  -d '{"task_id": "test-123"}'

# Expected response includes mock questionnaire with 5 questions
```
