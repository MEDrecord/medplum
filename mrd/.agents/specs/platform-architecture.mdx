# MEDrecord Platform Architecture

The MEDrecord platform is a multi-brand healthcare application ecosystem built on top of the Medplum FHIR server. All brands share the same SDK, Gateway, and infrastructure while maintaining distinct user experiences.

## Core Principles

### 1. Gateway-First Architecture

All data flows through the Gateway service. Brand apps never communicate directly with MedPlum, the GPU, or external services.

```
UI Component → @mrd/sdk hook → GatewayClient → Gateway API → Backend Service
```

### 2. Brand Separation

Each brand is a separate Next.js application with its own:
- Domain (healthtalk.ai, coachi.ai, medsafe.ai)
- Visual identity (colors, logo, typography)
- Feature flags
- Tenant configuration

All brands share:
- SDK (`@mrd/sdk`)
- UI components (`@mrd/ui`)
- Gateway service
- MedPlum FHIR backend

### 3. Server-Side Secrets

Sensitive operations and credentials exist only in the Gateway:

| Location | Contains |
|----------|----------|
| Brand Apps | No secrets, no direct API access |
| Gateway | MedPlum credentials, AI API keys, Twilio tokens |
| MedPlum | FHIR data, user records |

## Request Flow Example

### Template Creation

```
1. Clinician clicks "Create Template" in HealthTalk UI

2. UI Component:
   const { client } = useGateway();
   await client.templates.create({ title, type: 'note-template' });

3. GatewayClient:
   POST https://gateway.healthtalk.ai/api/templates
   Headers: Authorization: Bearer {token}, X-Brand: healthtalk

4. Gateway API Route:
   - Verifies JWT token
   - Extracts tenant from token
   - Calls MedPlum with server credentials
   - Returns created template

5. MedPlum:
   - Creates PlanDefinition resource
   - Returns FHIR resource

6. Response flows back through Gateway → SDK → UI
```
