# MedPlum Subscriptions

This document describes how MedPlum Subscriptions trigger the Communication Gateway for patient outreach.

## Overview

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  SUBSCRIPTION FLOW                                                          │
│                                                                             │
│  ┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌───────────┐ │
│  │ Brand App   │     │ MedPlum     │     │ Comms       │     │ Patient   │ │
│  │ creates     │────>│ Subscription│────>│ Gateway     │────>│ receives  │ │
│  │ Task        │     │ fires       │     │ sends       │     │ message   │ │
│  └─────────────┘     └─────────────┘     └─────────────┘     └───────────┘ │
│                                                                             │
│  POST Task           Webhook POST       WhatsApp/SMS/       Magic link     │
│  status=requested    to gateway         Email/Voice         to form        │
└─────────────────────────────────────────────────────────────────────────────┘
```

## Required Subscriptions

### 1. Task Created Subscription

Triggers when a new questionnaire task is created.

```json
{
  "resourceType": "Subscription",
  "id": "task-created-subscription",
  "status": "active",
  "reason": "Send questionnaire to patient via Communication Gateway",
  "criteria": "Task?status=requested&code=http://loinc.org|74468-0",
  "channel": {
    "type": "rest-hook",
    "endpoint": "https://comms.medrecord.nl/api/webhooks/task-created",
    "payload": "application/fhir+json",
    "header": [
      "X-Subscription-Secret: ${SUBSCRIPTION_SECRET}"
    ]
  }
}
```

### 2. Task Reminder Subscription

Triggers when a task is due for reminder (based on Task.restriction.period).

```json
{
  "resourceType": "Subscription",
  "id": "task-reminder-subscription",
  "status": "active",
  "reason": "Send reminder for incomplete questionnaire",
  "criteria": "Task?status=in-progress&code=http://loinc.org|74468-0",
  "channel": {
    "type": "rest-hook",
    "endpoint": "https://comms.medrecord.nl/api/webhooks/task-reminder",
    "payload": "application/fhir+json",
    "header": [
      "X-Subscription-Secret: ${SUBSCRIPTION_SECRET}"
    ]
  }
}
```

### 3. QuestionnaireResponse Created Subscription

Triggers when patient completes a questionnaire (for score calculation).

```json
{
  "resourceType": "Subscription",
  "id": "response-created-subscription",
  "status": "active",
  "reason": "Calculate score and notify clinician",
  "criteria": "QuestionnaireResponse?status=completed",
  "channel": {
    "type": "rest-hook",
    "endpoint": "https://comms.medrecord.nl/api/webhooks/response-completed",
    "payload": "application/fhir+json",
    "header": [
      "X-Subscription-Secret: ${SUBSCRIPTION_SECRET}"
    ]
  }
}
```

## Webhook Security

### HMAC Signature Validation

All webhooks from MedPlum include a signature header for validation.

```typescript
// Communication Gateway webhook handler
import { createHmac } from 'crypto';

function validateWebhook(request: Request): boolean {
  const signature = request.headers.get('X-Subscription-Secret');
  const body = await request.text();
  
  const expectedSignature = createHmac('sha256', process.env.SUBSCRIPTION_SECRET!)
    .update(body)
    .digest('hex');
  
  return signature === expectedSignature;
}
```

### IP Allowlisting

For additional security, allowlist MedPlum server IPs:

| Environment | MedPlum Server |
|-------------|----------------|
| Production | `medplum.medrecord.nl` |
| Staging | `medplum-staging.medrecord.nl` |

## MedPlum Bot: Score Calculation

When a QuestionnaireResponse is created, a MedPlum Bot calculates the score and creates an Observation.

### Bot Registration

```json
{
  "resourceType": "Bot",
  "id": "score-calculator-bot",
  "name": "Questionnaire Score Calculator",
  "runtimeVersion": "awslambda",
  "code": "// See implementation below"
}
```

### Bot Implementation

```typescript
import { BotEvent, MedplumClient } from '@medplum/core';
import { QuestionnaireResponse, Observation, Questionnaire } from '@medplum/fhirtypes';

export async function handler(
  medplum: MedplumClient,
  event: BotEvent<QuestionnaireResponse>
): Promise<void> {
  const response = event.input;
  
  // 1. Get the Questionnaire to check if scoring is enabled
  const questionnaireRef = response.questionnaire;
  const questionnaire = await medplum.readReference({ reference: questionnaireRef });
  
  // 2. Check for score extension
  const scoreExtension = questionnaire.extension?.find(
    ext => ext.url === 'http://hl7.org/fhir/uv/sdc/StructureDefinition/sdc-questionnaire-scoring'
  );
  
  if (!scoreExtension) {
    return; // No scoring configured
  }
  
  // 3. Calculate score
  const score = calculateScore(response, questionnaire);
  
  // 4. Create Observation
  const observation: Observation = {
    resourceType: 'Observation',
    status: 'final',
    code: {
      coding: [{
        system: 'http://loinc.org',
        code: questionnaire.code?.[0]?.code || '74465-6',
        display: questionnaire.title || 'Questionnaire Score'
      }]
    },
    subject: response.subject,
    effectiveDateTime: new Date().toISOString(),
    valueInteger: score.total,
    interpretation: [{
      coding: [{
        system: 'http://terminology.hl7.org/CodeSystem/v3-ObservationInterpretation',
        code: mapSeverityToCode(score.severity),
        display: score.severityLabel
      }]
    }],
    derivedFrom: [{ reference: `QuestionnaireResponse/${response.id}` }],
    component: score.itemScores.map(item => ({
      code: {
        coding: [{
          system: 'http://loinc.org',
          code: item.linkId
        }]
      },
      valueInteger: item.score
    }))
  };
  
  await medplum.createResource(observation);
  
  // 5. Update Task status to completed
  const task = await medplum.searchOne('Task', {
    focus: `QuestionnaireResponse/${response.id}`
  });
  
  if (task) {
    await medplum.updateResource({
      ...task,
      status: 'completed',
      output: [{
        type: { text: 'Score' },
        valueInteger: score.total
      }]
    });
  }
}

function calculateScore(
  response: QuestionnaireResponse, 
  questionnaire: Questionnaire
): { total: number; severity: string; severityLabel: string; itemScores: Array<{ linkId: string; score: number }> } {
  // Implementation based on questionnaire scoring rules
  // See fhir-extensions.mdx for score configuration format
}

function mapSeverityToCode(severity: string): string {
  const map: Record<string, string> = {
    'minimal': 'L',
    'mild': 'L', 
    'moderate': 'H',
    'moderately-severe': 'HH',
    'severe': 'HH'
  };
  return map[severity] || 'N';
}
```

## Task Lifecycle

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  TASK STATUS TRANSITIONS                                                    │
│                                                                             │
│  requested ──────> in-progress ──────> completed                           │
│      │                  │                   │                               │
│      │                  │                   └── QuestionnaireResponse       │
│      │                  │                       created + score calculated  │
│      │                  │                                                   │
│      │                  └── Patient opened magic link                       │
│      │                                                                      │
│      └── Task created, notification sent                                   │
│                                                                             │
│  At any point: ──────> cancelled (clinician cancels)                       │
│                ──────> failed (delivery failed after retries)              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### businessStatus Values

| businessStatus | Description |
|----------------|-------------|
| `queued` | Task created, waiting for delivery |
| `sending` | Communication Gateway processing |
| `sent` | Message delivered to channel |
| `delivered` | Delivery confirmed by provider |
| `read` | Patient opened message (if trackable) |
| `opened` | Patient clicked magic link |
| `reminder-sent` | Reminder notification sent |
| `failed` | Delivery failed after retries |

## Setup Instructions (DevOps)

### 1. Create Subscriptions in MedPlum

```bash
# Using MedPlum CLI
medplum login
medplum post Subscription subscription-task-created.json
medplum post Subscription subscription-response-created.json
medplum post Bot score-calculator-bot.json
```

### 2. Configure Environment Variables

**MedPlum Server:**
```env
SUBSCRIPTION_SECRET=<shared-secret-for-webhook-validation>
```

**Communication Gateway:**
```env
SUBSCRIPTION_SECRET=<same-shared-secret>
MEDPLUM_BASE_URL=https://medplum.medrecord.nl
MEDPLUM_CLIENT_ID=comms-gateway
MEDPLUM_CLIENT_SECRET=<client-secret>
```

### 3. Test Webhook Connectivity

```bash
# Create test task
curl -X POST https://medplum.medrecord.nl/fhir/R4/Task \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/fhir+json" \
  -d '{
    "resourceType": "Task",
    "status": "requested",
    "intent": "order",
    "code": {
      "coding": [{
        "system": "http://loinc.org",
        "code": "74468-0"
      }]
    },
    "for": { "reference": "Patient/test-patient" },
    "focus": { "reference": "Questionnaire/phq-9" }
  }'
```

Verify webhook received at Communication Gateway logs.
