# Security & Compliance

## 1. Kernprincipes

### 1.1 Non-negotiable Regels

| Regel | Beschrijving |
|-------|--------------|
| **Gateway Pattern** | Frontend → API Route → Gateway → Database. Altijd. |
| **Geen directe DB access** | Geen Supabase/ORM imports in UI code |
| **Server-side secrets** | Alle backend operaties (data, OpenAI, secrets) alleen server-side |
| **Auth verificatie** | Elk request geverifieerd met `auth.id` via gateway |
| **Geen localStorage voor auth** | Sessies alleen via HTTP-only cookies of gateway tokens |

### 1.2 Data Flow Vereisten

```plaintext
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   Browser    │ ──► │  API Route   │ ──► │   Gateway    │ ──► │   Database   │
│   (Client)   │     │  (Server)    │     │   Service    │     │   (Medplum)  │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
      │                     │                    │                     │
      │ ✗ Geen secrets      │ ✓ Secrets OK       │ ✓ Auth verified     │
      │ ✗ Geen DB access    │ ✓ Gateway calls    │ ✓ Tenant scoped     │
      │ ✗ Geen OpenAI       │ ✓ AI calls OK      │                     │
```

## 2. Authenticatie

### 2.1 Gateway Auth Verificatie

Elk API request MOET beginnen met auth verificatie:

```typescript
export async function GET(request: Request) {
  try {
    // ALTIJD eerste stap - geen code voor deze regel
    const auth = await verifyGatewayAuth(request);
    
    // Nu pas business logic
    const data = await fetchData(auth.tenant_id);
    
    return NextResponse.json({ data });
    
  } catch (error) {
    if (error instanceof GatewayAuthError) {
      return NextResponse.json(
        { error: { code: error.code, message: error.message } },
        { status: 401 }
      );
    }
    // ...
  }
}
```

### 2.2 Auth Token Structuur

```typescript
interface GatewayAuth {
  user_id: string;      // UUID van de gebruiker
  tenant_id: string;    // UUID van de organisatie
  brand: BrandId;       // 'healthtalk' | 'coachi' | 'medsafe'
  accessToken: string;  // JWT voor downstream calls
  roles: string[];      // User roles
}
```

### 2.3 Session Management

| Mechanisme | Gebruik | Veiligheid |
|------------|---------|------------|
| HTTP-only cookies | Same-origin requests | Standaard, meest veilig |
| X-Session-Id header | Cross-origin requests | Alleen indien nodig |
| CSRF token | Mutaties (POST/PUT/DELETE) | Verplicht voor forms |

## 3. CSRF Protection

### 3.1 Implementatie

```typescript
// CSRF token alleen voor same-origin mutaties
if ((isSameOrigin || isRelativeUrl) && method !== 'GET') {
  headers.set('X-CSRF-Token', csrfToken);
}
```

### 3.2 Regels

- CSRF token verplicht voor alle POST/PUT/PATCH/DELETE requests
- Token wordt gegenereerd door gateway bij sessie start
- Token moet matchen met sessie, anders 403 Forbidden

## 4. Data Isolation

### 4.1 Tenant Scoping

Alle queries worden automatisch gefilterd op tenant:

```typescript
// Medplum search met tenant scope
const bundle = await medplum.search('Questionnaire', {
  ...params,
  _project: auth.tenant_id  // Medplum Project = Tenant
});
```

### 4.2 Verboden Patterns

```typescript
// ❌ FOUT - Geen tenant check
const allData = await medplum.search('Patient');

// ❌ FOUT - Client-side filtering (data al gelekt)
const filtered = allData.filter(p => p.tenant === currentTenant);

// ✓ CORRECT - Server-side tenant scoping
const scoped = await medplum.search('Patient', {
  _project: auth.tenant_id
});
```

## 5. Input Validatie

### 5.1 Server-side Validatie

Alle input MOET server-side gevalideerd worden:

```typescript
export async function POST(request: Request) {
  const auth = await verifyGatewayAuth(request);
  const body = await request.json();
  
  // Valideer input
  if (!body.title || typeof body.title !== 'string') {
    return NextResponse.json(
      { error: { code: 'VALIDATION_ERROR', message: 'title is required' } },
      { status: 400 }
    );
  }
  
  // Sanitize
  const sanitizedTitle = sanitizeHtml(body.title);
  
  // ...
}
```

### 5.2 Parameterized Queries

```typescript
// ❌ FOUT - SQL Injection mogelijk
const query = `SELECT * FROM users WHERE id = '${userId}'`;

// ✓ CORRECT - Parameterized
const result = await medplum.search('Patient', {
  _id: userId  // Medplum handles parameterization
});
```

## 6. Secrets Management

### 6.1 Environment Variables

| Variable | Toegang | Gebruik |
|----------|---------|---------|
| `NEXT_PUBLIC_*` | Client + Server | Alleen publieke config |
| `OPENAI_API_KEY` | Server only | AI calls |
| `LOINC_USERNAME` | Server only | LOINC import |
| `MEDPLUM_CLIENT_SECRET` | Server only | Medplum auth |

### 6.2 Verboden in Client Code

```typescript
// ❌ FOUT - Secret in client bundle
const apiKey = process.env.OPENAI_API_KEY;

// ❌ FOUT - Hardcoded secret
const password = 'super-secret-123';

// ✓ CORRECT - Server-side only
// In app/api/ai/route.ts (server)
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });
```

## 7. Error Handling

### 7.1 Geen Sensitive Data in Errors

```typescript
// ❌ FOUT - Stack trace naar client
return NextResponse.json({ error: error.stack }, { status: 500 });

// ❌ FOUT - Database error details
return NextResponse.json({ error: error.message }, { status: 500 });

// ✓ CORRECT - Generic error
console.error('[HealthTalk] Error:', error);  // Log server-side
return NextResponse.json(
  { error: { code: 'INTERNAL_ERROR', message: 'Internal server error' } },
  { status: 500 }
);
```

### 7.2 Auth Error Event

```typescript
// Bij 401/403 wordt event gefired voor global handling
window.dispatchEvent(new CustomEvent('gateway:auth-error', {
  detail: { status: response.status, url }
}));
```

## 8. Audit Logging

### 8.1 Wat Te Loggen

| Event | Log Level | Data |
|-------|-----------|------|
| User login | INFO | user_id, tenant_id, timestamp |
| Resource created | INFO | resource_type, resource_id, user_id |
| Resource updated | INFO | resource_type, resource_id, user_id, changed_fields |
| Resource deleted | WARN | resource_type, resource_id, user_id |
| Auth failure | WARN | attempted_user, ip, timestamp |
| Permission denied | WARN | user_id, resource, action |

### 8.2 Wat NIET Te Loggen

- Wachtwoorden (ook niet gehashed)
- Volledige patient data
- API keys of tokens
- Sessie tokens

## 9. GDPR Compliance

### 9.1 Data Minimization

- Vraag alleen data op die nodig is
- Gebruik `_elements` parameter voor partial responses
- Bewaar geen onnodige kopieën

### 9.2 Right to Erasure

```typescript
// Patient data deletion moet cascaden
async function deletePatientData(patientId: string, auth: GatewayAuth) {
  // 1. Delete all related resources
  await medplum.deleteResource('Observation', { subject: patientId });
  await medplum.deleteResource('QuestionnaireResponse', { subject: patientId });
  await medplum.deleteResource('Appointment', { participant: patientId });
  
  // 2. Delete patient
  await medplum.deleteResource('Patient', patientId);
  
  // 3. Log deletion
  console.info('[GDPR] Patient data deleted', { patientId, deletedBy: auth.user_id });
}
```

## 11. Checklist voor Code Review

### API Routes

- [ ] `verifyGatewayAuth()` is eerste regel in handler
- [ ] Geen secrets in response
- [ ] Input gevalideerd en gesanitized
- [ ] Tenant scoping toegepast
- [ ] Errors zijn generic, details alleen in logs

### Client Components

- [ ] Geen `process.env.SECRET_*` imports
- [ ] Geen directe database calls
- [ ] Geen medical data in localStorage
- [ ] Auth errors worden afgehandeld

### Data Handling

- [ ] Parameterized queries
- [ ] Geen PII in logs
- [ ] HTTPS voor alle external calls
- [ ] Proper error boundaries
