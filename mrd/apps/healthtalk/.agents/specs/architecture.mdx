# HealthTalk Architectuur

## 1. Overzicht

HealthTalk is een AI-gestuurde conversatie-applicatie voor de gezondheidszorg, gebouwd op het Medplum FHIR platform. De applicatie ondersteunt meerdere merken (HealthTalk, Coachi, MedSafe) binnen een multi-tenant architectuur.

```plaintext
┌─────────────────────────────────────────────────────────────────────────┐
│                           FRONTEND (UI Layer)                           │
│  Next.js App Router │ shadcn/ui │ React Flow                            │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        API ROUTES (Server Layer)                        │
│  app/api/* │ Server Actions │ Server Components                         │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ gatewayFetch()
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                      GATEWAY SERVICES (Backend)                         │
│  Auth Gateway │ Template Service │ Consultation Service │ Medplum FHIR  │
└─────────────────────────────────────────────────────────────────────────┘
```

## 2. Kernprincipes

### 2.1 Non-negotiable Regels

| Regel | Beschrijving |
|-------|--------------|
| **Gateway Pattern** | Frontend → API Route → Gateway → Database. Altijd. |
| **Geen directe DB access** | Geen Supabase/ORM imports in UI code |
| **Server-side secrets** | Alle backend operaties (data, OpenAI, secrets) alleen server-side |
| **Auth verificatie** | Elk request geverifieerd met `auth.id` via gateway |
| **UI framework** | Alleen shadcn/ui + React Flow. Geen custom CSS, geen inline styles |

### 2.2 Gateway URLs

| Environment Variable | Service | Doel |
|-----|-----|-----|
| `NEXT_PUBLIC_GATEWAY_BASE_URL` | Auth Gateway | Authenticatie, sessie management |
| `NEXT_PUBLIC_TEMPLATE_SERVICE_GATEWAY_URL` | Template Service | Templates CRUD, secties, talen |
| `NEXT_PUBLIC_CONSULTATION_SERVICE_GATEWAY_URL` | Consultation Service | Appointments, rapport regeneratie |

## 6. Error Handling

### 6.1 Gateway Errors

```typescript
// Standaard error response format
interface GatewayErrorResponse {
  error: {
    code: string;
    message: string;
    details?: Record<string, unknown>;
  };
}

// Error codes
type GatewayErrorCode =
  | 'AUTH_REQUIRED'      // 401 - Niet ingelogd
  | 'FORBIDDEN'          // 403 - Geen toegang
  | 'NOT_FOUND'          // 404 - Resource niet gevonden
  | 'VALIDATION_ERROR'   // 400 - Validatie gefaald
  | 'INTERNAL_ERROR';    // 500 - Server fout
```

### 6.2 Auth Error Event

```typescript
// Bij 401/403 wordt een event gefired voor global handling
window.dispatchEvent(new CustomEvent('gateway:auth-error', {
  detail: { status: response.status, url }
}));
```
