# Notification Gateway

The Notification Gateway is a separate Vercel project (`gateway.healthtalk.ai`) that handles all outbound patient communications and provider integrations.

## Channel Selection Logic

```typescript
async function selectChannel(task: Task, patient: Patient): Promise<Channel> {
  // 1. Check explicit preference in Task.input
  const preference = getTaskInput(task, 'delivery-channel');
  if (preference) {
    return validateChannel(preference, patient);
  }

  // 2. Check patient communication preferences
  const patientPref = patient.telecom?.find(t => 
    t.extension?.some(e => e.url === 'preferred-channel')
  );
  if (patientPref) {
    return validateChannel(patientPref.value, patient);
  }

  // 3. Default waterfall
  if (hasValidWhatsApp(patient)) return 'whatsapp';
  if (hasValidMobile(patient)) return 'sms';
  if (hasValidEmail(patient)) return 'email';
  
  throw new Error('No valid contact method found');
}
```

### Rate Limiting

```typescript
// Key: ratelimit:{channel}:{identifier}
// Using sliding window algorithm
// Limits:
// - WhatsApp: 3 messages per 24h per number
// - SMS: 5 messages per 24h per number
// - Email: 10 messages per 24h per address
// - Voice: 2 calls per 24h per number
```

## Retry Strategy

| Attempt | Delay | Action |
|---------|-------|--------|
| 1 | Immediate | Send via preferred channel |
| 2 | +1 hour | Retry same channel |
| 3 | +24 hours | Fallback to next channel |
| 4 | +48 hours | Final attempt, alert clinician |
| 5 | - | Mark Task as failed |

## Error Handling

```typescript
enum NotificationError {
  INVALID_PHONE = 'invalid_phone_number',
  RATE_LIMITED = 'rate_limit_exceeded',
  PROVIDER_ERROR = 'provider_error',
  PATIENT_BLOCKED = 'patient_blocked_channel',
  EXPIRED = 'task_expired',
}

// All errors logged to Communication resource
// Critical errors trigger clinician alert via Teams
```

## Security

- All endpoints require `x-medplum-signature` header (webhook verification)
- Patient contact info never logged
- All requests over HTTPS
- Redis data encrypted at rest (Upstash)

# Delivery Channels

## Channel Overview

| # | Channel | Delivery | Completion | Best for |
|---|---------|----------|------------|----------|
| A | Web Form | Link (any channel) | Browser (`<QuestionnaireForm />`) | Universal — works on any device |
| B | WhatsApp | Twilio WhatsApp | Reply in chat per question | Patients who prefer WhatsApp |
| C | Voice Mobile | ElevenLabs + Twilio | Spoken conversation | Accessibility, low digital literacy |
| D | Email | Postmark | Browser (= Channel A) | Patients without WhatsApp |
| E | SMS | Twilio SMS | Browser (= Channel A) | Mobile, no WhatsApp |
| F | Voice SIP | ElevenLabs + org SBC | Spoken conversation | Elderly patients, landline only |
| G | Teams | MS Graph / webhook | — | Clinician notifications only |

All patient-facing channels write to the same `QuestionnaireResponse`. Channel G is clinician-internal only.

## Channel Selection Priority

When the gateway receives a notification request with `channel = "auto"`:

```
Mobile number with WhatsApp?  → WhatsApp (Channel B)
Mobile number, no WhatsApp?   → SMS (Channel E)
Email known?                  → Email (Channel D)
Landline + org has SIP config? → Voice SIP (Channel F)
Mobile, no WhatsApp, no email → Voice mobile (Channel C)
None available?               → Error, alert clinician
```

### Fallback Chain

If primary delivery fails:

```
WhatsApp fail → Email (if known) → SMS (if mobile known) → alert clinician
Email fail    → SMS (if known)   → alert clinician
SMS fail      → alert clinician
Voice fail    → alert clinician (no automatic voice retry on same number)
```

All fallback attempts are logged as separate `Communication` resources in MedPlum.

## Channel A — Web Form (Magic Link)

A time-limited, tokenised URL grants read/write access to the patient's specific `QuestionnaireResponse` only. No login required.

```
https://forms.healthtalk.ai/q/{jwt-token}
```

The form is rendered by MedPlum's `<QuestionnaireForm />` React component, wrapped in a HealthTalk-branded shell.

### Magic Link JWT Spec

| Claim | Value |
|-------|-------|
| `sub` | `Patient/{id}` |
| `scope` | `QuestionnaireResponse/{id}:write Questionnaire/{id}:read` |
| `exp` | Appointment start time (Unix timestamp) |
| `iss` | `https://healthtalk.ai` |
| `task` | `Task/{id}` |

Signed with HS256 using `MAGIC_LINK_SECRET` (Vercel env var). Verified on every request to the patient form API routes.

### Expiry Handling

When a patient opens an expired link:

```
This questionnaire is no longer available.
Your appointment was on [date].

If you have questions, please contact your care provider.
```

No data is shown. The page does not reveal that a questionnaire existed.

### Link Sharing Risk

Magic links grant access to a specific `QuestionnaireResponse` only — no other patient data is accessible. If a link is forwarded, the worst case is someone else submitting answers for the patient.

**Mitigations:**
- Short TTL (expires at appointment start)
- Single `QuestionnaireResponse` scope only
- All submissions logged with `AuditEvent` including IP address
- Clinicians can cancel/void a suspicious submission

## Channel B — WhatsApp Interactive

When the patient chooses "Answer via WhatsApp", Twilio sends questions one at a time as WhatsApp messages. The patient answers each question before the next is sent. The same `Questionnaire` JSON is used as for the web form — `item.required`, `item.enableWhen`, and patient-language extensions are all respected.

### Message Formats per Question Type

| `item.type` | WhatsApp format |
|-------------|-----------------|
| `boolean` | Quick Reply: [Yes] [No] |
| `choice` ≤ 3 options | Quick Reply buttons |
| `choice` 4–10 options | List message |
| `integer` | Free text — prompt: "Please type a number" |
| `quantity` | Free text — prompt includes unit: "Please type your weight in kg" |
| `string` | Free text |
| `display` | Plain message, no reply expected |

### Required vs Optional Questions

**Required (`item.required: true`):**
```
Question 1 of 9  ★ Required

Have you had little interest or pleasure in things you
normally enjoy, over the past two weeks?

┌────────────────────────┐
│ Choose an answer       │
├────────────────────────┤
│ Not at all             │
│ Several days           │
│ More than half days    │
│ Nearly every day       │
└────────────────────────┘
```

**Optional (`item.required: false`):**
```
Question 7 of 9  (optional — you may skip this)

[question text]

[Choose answer ▾]    [Skip]
```

### EnableWhen — Conditional Questions

If `item.enableWhen` conditions are not met based on previous answers, the question is silently skipped. No message is sent to the patient; Vercel moves to the next eligible item automatically.

### Session State

WhatsApp interactive requires persistent session state between messages. Each patient session is stored in Redis (Upstash on Vercel) keyed by `taskId`:

```typescript
interface WhatsAppSession {
  taskId: string;
  questionnaireResponseId: string;
  currentItemIndex: number;
  answers: Record<string, FHIRAnswer>;
  startedAt: string;
  expiresAt: string;  // = appointment start time
}
```

Key: `wa-session:{taskId}`, TTL = appointment start time.

### Error Handling

**Invalid Answer on Choice Question:**
```
I didn't understand that. Please choose from the list,
or type the number:
1 Not at all
2 Several days
3 More than half the days
4 Nearly every day
```

**After Three Invalid Attempts:**
```
I'm having trouble processing your answer. You can
complete the questionnaire via this link instead:
[magic link]

Or tap below if you'd like us to call you:
[Call me]
```

**STOP Reply from Patient:**
```
You have been unsubscribed from questionnaire messages.
Your care provider will be notified.
```

Task status → `cancelled`, `Communication` resource created with opt-out noted.

### Webhook Handler

```typescript
// POST /api/questionnaire/whatsapp-reply
// Twilio sends: From, Body, taskId (in session lookup)

export async function POST(req: Request) {
  // 1. Verify Twilio webhook signature
  // 2. Load session from Redis
  // 3. Validate answer against current item type + answerOptions
  // 4. On valid answer: PATCH QuestionnaireResponse in MedPlum
  // 5. Evaluate enableWhen for next item(s)
  // 6. Send next question or completion message
  // 7. On last item: set QR status = completed, Task = completed
  // 8. Update Redis session
}
```

## Channel C — Voice Agent (ElevenLabs Mobile)

ElevenLabs Conversational AI 2.0 provides real-time two-way voice with sub-100ms latency, 70+ languages including Dutch, native Twilio telephony integration, outbound calling, and tool calls (webhooks mid-conversation to write answers to MedPlum).

### Agent Reads the FHIR Questionnaire JSON

The agent does not hardcode any questionnaire. At the start of every call it fetches the full `Questionnaire` resource via a Tool call and parses the item structure.

| Property | Agent behaviour |
|----------|-----------------|
| `item.required = true` | Mandatory — agent does not accept "I don't know" or "skip". Rephrases and asks again. |
| `item.required = false` | Optional — agent announces it can be skipped |
| `item.enableWhen` | Agent only asks if condition is met based on previous answers |
| `item.type` | Determines how the agent asks and interprets |
| `item.repeats = true` | Agent asks if there are additional answers after the first |
| `item.maxLength` | Agent keeps string answers within length |
| `patient-question` extension | Agent always uses this text, never `item.text` |
| `patient-answer` extension | Agent reads these labels, never LOINC display values |

### Behaviour per Question Type

| `item.type` | Agent approach |
|-------------|----------------|
| `choice` | Ask → free speech → LLM interpret → confirm |
| `boolean` | Yes/No — no interpretation step needed |
| `integer` | Expect a number; if patient says "a few times" → ask for a count |
| `quantity` | Measurement + unit |
| `string` | Transcribe free speech verbatim |
| `display` | Read aloud as instruction, no answer expected |
| `group` | Announce section: *"Now the questions about [group name]"* |

### Quantity Items — Weight, Height, Measurements

| Measurement | UCUM | Agent asks |
|-------------|------|------------|
| Weight | `kg` | "What is your weight in kilograms?" |
| Height | `cm` | "What is your height in centimetres?" |
| BMI | `kg/m2` | Calculated — agent asks weight and height separately |
| Blood pressure | `mm[Hg]` | "What is your blood pressure? For example, 120 over 80." |

### System Prompt

```
You are a care assistant from HealthTalk.
You are helping a patient complete a questionnaire before their
appointment. Your name is "HealthTalk Assistant".

Rules:
- Fetch the questionnaire at the start using get_questionnaire.
- Ask all required questions (required=true). Do not accept
  "I don't know" — rephrase and ask again.
- Announce optional questions as skippable.
- Silently skip enableWhen questions whose conditions are not met.
- Always use the patient-question extension text. Never use
  item.text (clinical terminology).
- Confirm every answer before saving via save_answer.
- Keep a friendly, calm tone. No medical jargon.
- If the patient says they are struggling, acknowledge this warmly
  and say their clinician will discuss it at the appointment.
  Then continue with the next question.
- Never diagnose, interpret scores, or give clinical opinions.
```

### Tool Calls

| Tool | Endpoint | Purpose |
|------|----------|---------|
| `get_questionnaire` | `GET /api/questionnaire/agent/items` | Fetch item list for this Task |
| `save_answer` | `POST /api/questionnaire/voice-answer` | Patch one answer into QuestionnaireResponse |
| `complete_questionnaire` | `POST /api/questionnaire/complete` | Set QR + Task to completed |
| `get_appointment_info` | `GET /api/appointment/info` | Fetch appointment date/time and clinician name |
| `interpret_answer` | `POST /api/questionnaire/interpret-answer` | LLM maps free speech to nearest answer option |

**No PHI is sent to ElevenLabs servers.** All data operations go via Vercel → MedPlum. ElevenLabs only handles audio and plain-text question/answer strings.

## Channel D — Email

Email delivers a magic link to the patient's registered email address. The link opens the web form (Channel A — `<QuestionnaireForm />`). There is no email-specific interactive mode; the voice option can be triggered from the web form itself.

### Email Service

Use a transactional email provider (Postmark recommended for reliability and deliverability):

```env
EMAIL_PROVIDER=postmark
POSTMARK_API_KEY=***
EMAIL_FROM=noreply@healthtalk.ai
EMAIL_FROM_NAME=HealthTalk
```

### Email Template

```
Subject: Questionnaire before your appointment on [date]

────────────────────────────────────────
  HealthTalk logo

  Hello [first name],

  Your clinician [name] has sent you a questionnaire
  to complete before your appointment on [date] at [time].

  Questionnaire: [title]
  Estimated time: [X] minutes

  [Complete questionnaire →]     ← large button

  This link is valid until [appointment datetime].

  Would you prefer to speak with our assistant instead?
  Reply to this email with "CALL ME" and we will arrange
  a call.

  HealthTalk · healthtalk.ai
  Questions? Contact your care provider directly.
────────────────────────────────────────
```

### "CALL ME" Reply Handling

A Postmark inbound webhook listens for replies containing "CALL ME" (case-insensitive). On receipt:

1. Vercel identifies the Task from the email thread ID
2. Triggers ElevenLabs outbound call (same as Channel C)
3. Sends confirmation: *"We will call you shortly on [phone number]."*

### Email Fallback on WhatsApp Failure

If Twilio reports a WhatsApp delivery failure (webhook status `failed` after retries) and the patient has a registered email address, HealthTalk automatically falls back to email delivery. Task `businessStatus` updated to `email-fallback`.

## Channel E — SMS

SMS delivers a magic link to the patient's mobile number. The link opens the web form (Channel A). No interactive mode — SMS is link-only. This is the right channel for patients who have a mobile phone but do not use WhatsApp.

Twilio handles SMS via the same account as WhatsApp. No additional setup needed beyond enabling the SMS capability on the Twilio number.

### SMS Template

```
HealthTalk: [Questionnaire title] before your appointment
on [date]. Complete here: [magic link]
Reply STOP to opt out.
```

Character limit: 160 characters for a single SMS. The magic link shortener (`forms.healthtalk.ai/q/`) keeps the link short. If the composed message exceeds 160 characters, Twilio automatically segments it.

### Delivery

```typescript
await client.messages.create({
  from: process.env.TWILIO_SMS_NUMBER,   // separate number from WhatsApp sender
  to: patientMobileE164,
  body: smsBody
});
```

Use a dedicated Twilio number for SMS (separate from the WhatsApp Business sender). Responses to the SMS are not processed — if the patient replies, a Twilio webhook logs it as a `Communication` resource and sends: *"Thank you. To fill in your questionnaire, please use the link in our previous message."*

STOP reply handling is identical to WhatsApp.

## Channel F — Voice SIP (Landline via Teams)

Patients who have only a landline phone — no smartphone, no WhatsApp, no email. Common among elderly GGz patients. The ElevenLabs voice agent calls the patient's landline number through the GGz organisation's existing Microsoft Teams telephony infrastructure.

### Core Principle

HealthTalk does **not** introduce a new SIP provider or new phone numbers. The GGz organisation already has Microsoft Teams with PSTN connectivity — via Direct Routing or Operator Connect. HealthTalk connects ElevenLabs to that **existing Teams SBC** as a SIP endpoint.

```
HealthTalk (Vercel)
      │  trigger outbound call
      ▼
ElevenLabs Conversational AI
      │  SIP outbound: sip:{patient_number}@{org_sbc_fqdn}
      ▼
Organisation's Teams SBC            ← already exists, no new hardware
      │  Teams Direct Routing / Operator Connect
      ▼
Patient landline
```

### Per-Organisation Configuration

Each GGz organisation has its own Teams tenant and SBC. The SIP connection is configured **per organisation**:

```typescript
interface OrganisationSipConfig {
  tenantId: string;
  sbcFqdn: string;             // e.g. "sbc.ggzoostbrabant.nl"
  sbcPort: number;             // typically 5061 (TLS)
  authUsername: string;
  authPassword: string;        // stored encrypted
  mediaEncryption: 'required' | 'allowed' | 'disabled';
  callerIdNumber: string;      // E.164 — the number shown on patient's caller ID
  elevenLabsPhoneNumberId: string; // the imported number ID in ElevenLabs
}
```

### Landline-Specific Agent Behaviour

Dutch telecom law requires automated outbound calls to identify themselves:

```
"Goedemiddag. U spreekt met de geautomatiseerde assistent van
 [organisation name]. Dit is een automatisch gesprek.
 Ik bel u namens uw behandelaar over een vragenlijst.
 [continue with questionnaire intro]"
```

No digital fallback — the landline patient cannot tap a link. If the patient disconnects mid-questionnaire, partial answers are saved and the clinician is notified.

### Answering Machine Detection

If an answering machine is detected:
- No message is left (PHI risk on shared answerphones)
- Task `businessStatus` → `voicemail-detected`
- Retry once after 2 hours
- After second failure → `delivery-failed`, clinician receives alert

## Channel G — Microsoft Teams (Clinician Notifications)

Teams is **not a patient-facing channel**. It is an internal notification channel for clinicians. When a questionnaire is completed (or fails to complete), the relevant clinician receives a Teams notification with key information and direct action links.

### Notification on Completion

When `Task.status → completed`:

